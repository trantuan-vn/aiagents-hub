Hướng dẫn lọc một cặp “Tên yêu cầu số liệu – SQL” từ ứng dụng MySQL

Bấm đúng một chức năng, báo cáo hoặc tra cứu trên ứng dụng, bắt lại các câu SQL mà MySQL vừa chạy, rồi chọn ra câu SQL trả số liệu để lưu thành một cặp có định danh.

Tổng quan

Mỗi lần người dùng bấm một chức năng, ứng dụng gửi một hoặc nhiều câu SQL tới MySQL. MySQL lưu các câu này trong Performance Schema (các bảng events_statements_history, events_statements_history_long) kèm thời điểm chạy và số dòng trả về. Nếu chỉ có một người thao tác trong một khoảng thời gian ngắn, ta có thể lọc theo thời gian để biết chính xác chức năng đó đã sinh ra những SQL nào.

Chỉ thực hiện trên môi trường test

Hướng dẫn này có lệnh làm sạch bộ nhớ SQL và bật general log, có thể ảnh hưởng hiệu năng nếu chạy trên môi trường đang vận hành.

Điều kiện và chuẩn bị

  • Môi trường test, chỉ một người thao tác ứng dụng trong suốt thời gian lấy.
  • Tài khoản có quyền PROCESS, SELECT trên performance_schema và SUPER (để bật/tắt log).
  • Biết user MySQL mà ứng dụng dùng để kết nối. Trong tài liệu này dùng ví dụ app_user; hãy thay bằng user thực tế.
  • Công cụ chạy SQL: MySQL Workbench, DBeaver hoặc mysql client.
  • Performance Schema đã được bật (mặc định bật từ MySQL 5.7 trở lên).

2

Xác định session của ứng dụng

Cho ứng dụng đăng nhập và để ở trạng thái chờ, chưa bấm gì. Sau đó chạy:

SQL
SELECT id, user, host, db, command, time, state, info
FROM   information_schema.processlist
WHERE  user = 'app_user'
ORDER  BY id DESC;

Nếu ứng dụng dùng connection pool, bạn sẽ thấy nhiều session. Cứ ghi lại tất cả; Bước 3 và 7 không phụ thuộc vào một session cụ thể.

3

Làm sạch bộ nhớ SQL Chỉ trên test

MySQL không có lệnh FLUSH SHARED_POOL như Oracle. Thay vào đó, ta xoá lịch sử câu lệnh trong Performance Schema để mọi SQL xuất hiện sau đó chắc chắn đến từ thao tác của bạn:

SQL
TRUNCATE TABLE performance_schema.events_statements_history;
TRUNCATE TABLE performance_schema.events_statements_history_long;
TRUNCATE TABLE performance_schema.events_statements_summary_by_digest;

Bước này giúp mọi SQL xuất hiện sau đó chắc chắn đến từ thao tác của bạn, và MySQL ghi nhận lại giá trị tham số ở lần chạy đầu tiên của mỗi SQL.

Nếu không được phép chạy lệnh này, bỏ qua bước 3 và dựa vào mốc thời gian ở Bước 4 và 6.

7

Liệt kê SQL phát sinh

Khi chạy, công cụ sẽ hỏi giá trị t0 và t1; nhập đúng định dạng YYYY-MM-DD HH24:MI:SS.

SQL
SELECT THREAD_ID, EVENT_ID, EVENT_NAME,
       TIMER_WAIT/1000000000 AS elapsed_ms,
       ROWS_SENT, ROWS_EXAMINED,
       DATE_FORMAT(TIMER_START/1000000000000 + INTERVAL 0 SECOND,
                   '%Y-%m-%d %H:%i:%s') AS start_time,
       SUBSTR(SQL_TEXT, 1, 150) AS sql_preview
FROM   performance_schema.events_statements_history_long
WHERE  SQL_TEXT IS NOT NULL
  AND  SQL_TEXT NOT LIKE '%performance_schema%'
  AND  SQL_TEXT NOT LIKE '%information_schema%'
  AND  SQL_TEXT NOT LIKE '%mysql.%'
  AND  TIMER_START BETWEEN UNIX_TIMESTAMP('&t0')*1000000000000
                        AND UNIX_TIMESTAMP('&t1')*1000000000000
ORDER  BY TIMER_START, TIMER_WAIT DESC;

Nếu ứng dụng parse SQL dưới schema khác user đăng nhập, hãy lọc thêm bằng CURRENT_SCHEMA hoặc join với events_statements_current để lấy THREAD_ID tương ứng.

Để lọc theo user cụ thể, dùng performance_schema.threads:

SQL
SELECT t.PROCESSLIST_USER, t.PROCESSLIST_HOST, t.PROCESSLIST_DB,
       e.SQL_TEXT, e.ROWS_SENT, e.ROWS_EXAMINED,
       e.TIMER_WAIT/1000000000 AS elapsed_ms
FROM   performance_schema.events_statements_history_long e
JOIN   performance_schema.threads t ON t.THREAD_ID = e.THREAD_ID
WHERE  t.PROCESSLIST_USER = 'app_user'
  AND  e.SQL_TEXT IS NOT NULL
ORDER  BY e.TIMER_START;
8

Chọn SQL “trả số liệu”

Một lần bấm thường sinh từ 3 đến 20 SQL. Giữ lại câu SQL thoả các điều kiện sau:

  • Bắt đầu bằng SELECT hoặc WITH.
  • Truy vấn bảng nghiệp vụ (doanh thu, đơn hàng, khách hàng...), không phải bảng cấu hình, phân quyền, menu hay log.
  • ROWS_SENT lớn hơn 0 và hợp lý: báo cáo tổng hợp thì ít dòng, danh sách chi tiết thì nhiều dòng.
  • Thường là SQL có elapsed_ms lớn nhất, và chứa các cột giống tiêu đề cột trên báo cáo.

Lấy toàn văn SQL đã chọn:

SQL
SELECT SQL_TEXT
FROM   performance_schema.events_statements_history_long
WHERE  EVENT_ID = &event_id AND THREAD_ID = &thread_id;
9

Lấy giá trị tham số (bind)

MySQL không có view bind capture như Oracle. Có hai cách:

Cách 1: Dùng Performance Schema với prepared statement

SQL
-- Xem prepared statement và tham số
SELECT * FROM performance_schema.prepared_statements_instances;

Cách 2: Bật general log (chỉ trên test)

SQL
SET GLOBAL general_log = 'ON';
SET GLOBAL log_output = 'TABLE';  -- hoặc 'FILE'

Sau đó xem log:

SQL
SELECT event_time, user_host, thread_id, server_id,
       command_type, argument
FROM   mysql.general_log
WHERE  user_host LIKE '%app_user%'
  AND  event_time BETWEEN '&t0' AND '&t1'
ORDER  BY event_time;
Lưu ý

General log ghi tất cả câu lệnh, kể cả những câu không phải prepared statement. Với prepared statement, MySQL ghi cả câu Prepare và Execute cùng tham số.

Cách bắt bằng general log (khi cần chắc chắn về giá trị bind)

Dùng thay cho các Bước 3 đến 7, hoặc chạy song song để bổ sung giá trị tham số.

a. Bật general log trước khi bấm

SQL
SET GLOBAL general_log = 'ON';
SET GLOBAL log_output = 'TABLE';

b. Bấm đúng một chức năng

Thực hiện như Bước 5.

c. Tắt general log

SQL
SET GLOBAL general_log = 'OFF';

d. Tìm log của session vừa chạy

SQL
SELECT event_time, user_host, thread_id, server_id,
       command_type, argument
FROM   mysql.general_log
WHERE  user_host LIKE '%app_user%'
  AND  event_time BETWEEN '&t0' AND '&t1'
ORDER  BY event_time;

e. Đọc file log (nếu dùng log_output = 'FILE')

  • Nhờ DBA lấy file từ server. Tìm các dòng có Query (câu SQL) và Prepare / Execute (giá trị tham số).
  • Hoặc xem trực tiếp bằng SQL nếu dùng log_output = 'TABLE' như trên.
SQL
SHOW VARIABLES LIKE 'general_log_file';
SHOW VARIABLES LIKE 'log_output';
Lưu ý về mysqlbinlog

mysqlbinlog chỉ đọc binary log, không hiển thị giá trị bind của prepared statement trừ khi binlog_format = 'ROW' và có đủ thông tin. Muốn thấy bind phải đọc general log gốc.

Dọn dẹp sau khi hoàn tất

  • Đảm bảo general log đã được tắt (bước c ở phần Trace).
  • Xoá file log hoặc truncate bảng mysql.general_log nếu chứa dữ liệu nhạy cảm.
  • Lưu phiếu ghi chép cùng cặp thông tin đã lấy.
Tài liệu hướng dẫn nội bộ. Ví dụ dùng user app_user; thay bằng thông tin thực tế của môi trường.
