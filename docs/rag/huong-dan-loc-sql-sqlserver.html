Hướng dẫn lọc một cặp “Tên yêu cầu số liệu – SQL” từ ứng dụng SQL Server

Bấm đúng một chức năng, báo cáo hoặc tra cứu trên ứng dụng, bắt lại các câu SQL mà SQL Server vừa chạy, rồi chọn ra câu SQL trả số liệu để lưu thành một cặp có định danh.

  2. Bấm một chức năng

Tổng quan

Mỗi lần người dùng bấm một chức năng, ứng dụng gửi một hoặc nhiều câu SQL tới SQL Server. SQL Server lưu các câu này trong bộ nhớ đệm kế hoạch thực thi (plan cache), truy cập được qua các DMV như sys.dm_exec_query_stats, sys.dm_exec_sql_text, sys.dm_exec_requests và sys.dm_exec_sessions kèm thời điểm chạy và số dòng trả về. Nếu chỉ có một người thao tác trong một khoảng thời gian ngắn, ta có thể lọc theo thời gian để biết chính xác chức năng đó đã sinh ra những SQL nào.

Chỉ thực hiện trên môi trường test

Hướng dẫn này có lệnh làm sạch plan cache và bật Extended Events, có thể ảnh hưởng hiệu năng nếu chạy trên môi trường đang vận hành.

Điều kiện và chuẩn bị

  • Môi trường test, chỉ một người thao tác ứng dụng trong suốt thời gian lấy.
  • Tài khoản có quyền VIEW SERVER STATE (để đọc DMV) và ALTER ANY DATABASE hoặc sysadmin (để xoá plan cache, bật Extended Events).
  • Biết login SQL Server mà ứng dụng dùng để kết nối. Trong tài liệu này dùng ví dụ app_user; hãy thay bằng login thực tế.
  • Công cụ chạy SQL: SQL Server Management Studio (SSMS), Azure Data Studio hoặc sqlcmd.
  • Biết database mà ứng dụng kết nối tới (dùng để lọc theo dbid).

Xác định session của ứng dụng

Cho ứng dụng đăng nhập và để ở trạng thái chờ, chưa bấm gì. Sau đó chạy:

SQL
SELECT s.session_id, s.login_name, s.host_name, s.program_name,
       s.status, s.login_time, s.last_request_start_time
FROM   sys.dm_exec_sessions s
WHERE  s.login_name = 'app_user'
ORDER  BY s.login_time DESC;

Nếu ứng dụng dùng connection pool, bạn sẽ thấy nhiều session. Cứ ghi lại tất cả; Bước 3 và 7 không phụ thuộc vào một session cụ thể.

3

Làm sạch bộ nhớ SQL Chỉ trên test

SQL Server không có lệnh FLUSH SHARED_POOL như Oracle. Thay vào đó, ta xoá plan cache để mọi SQL xuất hiện sau đó chắc chắn đến từ thao tác của bạn:

SQL
-- Xoá toàn bộ plan cache (chỉ trên test)
DBCC FREEPROCCACHE;

-- Hoặc chỉ xoá plan cache của một database cụ thể
-- DBCC FLUSHPROCINDB (<dbid>);

Bước này giúp mọi SQL xuất hiện sau đó chắc chắn đến từ thao tác của bạn.

Nếu không được phép chạy lệnh này, bỏ qua bước 3 và dựa vào mốc thời gian ở Bước 4 và 6.

7

Liệt kê SQL phát sinh

Khi chạy, công cụ sẽ hỏi giá trị t0 và t1; nhập đúng định dạng YYYY-MM-DD HH24:MI:SS.

SQL
SELECT qs.sql_handle, qs.plan_handle, qs.execution_count,
       qs.total_rows, qs.last_rows,
       qs.total_elapsed_time/1000.0 AS total_elapsed_ms,
       qs.last_elapsed_time/1000.0  AS last_elapsed_ms,
       qs.creation_time, qs.last_execution_time,
       DB_NAME(st.dbid) AS db_name,
       SUBSTRING(st.text, 1, 200) AS sql_preview
FROM   sys.dm_exec_query_stats qs
CROSS APPLY sys.dm_exec_sql_text(qs.sql_handle) st
WHERE  qs.last_execution_time BETWEEN '&t0' AND '&t1'
  AND  st.text NOT LIKE '%sys.dm_%'
  AND  st.text NOT LIKE '%sys.%'
ORDER  BY qs.last_execution_time, qs.last_elapsed_time DESC;

Nếu ứng dụng chạy dưới login khác, hãy join với sys.dm_exec_sessions để lọc theo login_name, hoặc lọc theo DB_NAME(st.dbid) cho database nghiệp vụ.

Để lọc theo login cụ thể, dùng thêm sys.dm_exec_sessions:

SQL
SELECT s.login_name, s.host_name, s.program_name,
       r.session_id, r.status, r.start_time,
       SUBSTRING(st.text, 1, 200) AS sql_preview
FROM   sys.dm_exec_requests r
JOIN   sys.dm_exec_sessions s ON s.session_id = r.session_id
CROSS APPLY sys.dm_exec_sql_text(r.sql_handle) st
WHERE  s.login_name = 'app_user'
ORDER  BY r.start_time;
8

Chọn SQL “trả số liệu”

Một lần bấm thường sinh từ 3 đến 20 SQL. Giữ lại câu SQL thoả các điều kiện sau:

  • Bắt đầu bằng SELECT hoặc WITH.
  • Truy vấn bảng nghiệp vụ (doanh thu, đơn hàng, khách hàng...), không phải bảng cấu hình, phân quyền, menu hay log.
  • last_rows lớn hơn 0 và hợp lý: báo cáo tổng hợp thì ít dòng, danh sách chi tiết thì nhiều dòng.
  • Thường là SQL có last_elapsed_ms lớn nhất, và chứa các cột giống tiêu đề cột trên báo cáo.

Lấy toàn văn SQL đã chọn:

SQL
SELECT st.text AS sql_fulltext
FROM   sys.dm_exec_sql_text(&sql_handle) st;
9

Lấy giá trị tham số (bind)

SQL Server không có view bind capture như Oracle. Có hai cách:

Cách 1: Dùng sys.dm_exec_sql_text với statement_start_offset

SQL
-- Lấy câu SQL cụ thể trong batch kèm tham số hoá
SELECT SUBSTRING(st.text,
                 (qs.statement_start_offset/2) + 1,
                 ((CASE qs.statement_end_offset
                       WHEN -1 THEN DATALENGTH(st.text)
                       ELSE qs.statement_end_offset
                   END - qs.statement_start_offset)/2) + 1) AS statement_text
FROM   sys.dm_exec_query_stats qs
CROSS APPLY sys.dm_exec_sql_text(qs.sql_handle) st
WHERE  qs.sql_handle = &sql_handle;

Cách 2: Bật Extended Events để bắt tham số bind (chỉ trên test)

SQL
-- Xem hướng dẫn đầy đủ ở phần "Cách bắt bằng Extended Events" bên dưới
Cột tham số không đủ?

SQL Server không lưu giá trị bind trong plan cache. Khi cần chính xác giá trị bind, hãy dùng Extended Events với event sql_statement_completed và action sql_text, query_hash.

Cách bắt bằng Extended Events (khi cần chắc chắn về giá trị bind)

Dùng thay cho các Bước 3 đến 7, hoặc chạy song song để bổ sung giá trị tham số.

a. Tạo session Extended Events trước khi bấm

SQL
CREATE EVENT SESSION [catch_app_sql] ON SERVER
ADD EVENT sqlserver.sql_statement_completed(
    ACTION(sqlserver.sql_text, sqlserver.database_name,
           sqlserver.username, sqlserver.client_hostname,
           sqlserver.query_hash, sqlserver.query_plan_hash)
    WHERE sqlserver.username = N'app_user'
)
ADD TARGET package0.ring_buffer
WITH (MAX_MEMORY = 4096 KB, EVENT_RETENTION_MODE = ALLOW_SINGLE_EVENT_LOSS);
GO
ALTER EVENT SESSION [catch_app_sql] ON SERVER STATE = START;
GO

b. Bấm đúng một chức năng

Thực hiện như Bước 5.

c. Dừng session Extended Events

SQL
ALTER EVENT SESSION [catch_app_sql] ON SERVER STATE = STOP;
GO

d. Đọc dữ liệu đã bắt

SQL
SELECT
    n.value('(@timestamp)[1]', 'datetime2')       AS event_time,
    n.value('(action[@name="username"]/value)[1]', 'nvarchar(128)') AS username,
    n.value('(action[@name="client_hostname"]/value)[1]', 'nvarchar(128)') AS host,
    n.value('(action[@name="database_name"]/value)[1]', 'nvarchar(128)') AS db_name,
    n.value('(data[@name="statement"]/value)[1]', 'nvarchar(max)') AS statement,
    n.value('(data[@name="row_count"]/value)[1]', 'bigint') AS row_count,
    n.value('(data[@name="duration"]/value)[1]', 'bigint') AS duration_us,
    n.value('(action[@name="query_hash"]/value)[1]', 'varchar(64)') AS query_hash
FROM (
    SELECT CAST(t.target_data AS XML) AS xdata
    FROM sys.dm_xe_session_targets t
    JOIN sys.dm_xe_sessions s ON s.address = t.event_session_address
    WHERE s.name = 'catch_app_sql' AND t.target_name = 'ring_buffer'
) AS x
CROSS APPLY x.xdata.nodes('RingBufferTarget/event') AS e(n)
ORDER BY event_time;
Lưu ý về giá trị bind

Event sql_statement_completed trả về câu SQL kèm giá trị tham số đã được thay thế (nếu ứng dụng dùng prepared statement, SQL Server có thể hiển thị @P1; nếu dùng sp_executesql, giá trị bind thường xuất hiện trong statement). Để bắt rõ ràng hơn, thêm event sql_batch_completed và action sql_text.

e. Dọn dẹp session

SQL
DROP EVENT SESSION [catch_app_sql] ON SERVER;
GO

Dọn dẹp sau khi hoàn tất

  • Đảm bảo Extended Events session đã được dừng và xoá (bước e ở phần Trace).
  • Xoá file log hoặc bảng tạm nếu chứa dữ liệu nhạy cảm.
  • Lưu phiếu ghi chép cùng cặp thông tin đã lấy.
Tài liệu hướng dẫn nội bộ. Ví dụ dùng login app_user; thay bằng thông tin thực tế của môi trường.
