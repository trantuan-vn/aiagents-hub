Hướng dẫn lọc một cặp “Tên yêu cầu số liệu – SQL” từ ứng dụng PostgreSQL

Bấm đúng một chức năng, báo cáo hoặc tra cứu trên ứng dụng, bắt lại các câu SQL mà PostgreSQL vừa chạy, rồi chọn ra câu SQL trả số liệu để lưu thành một cặp có định danh.

  1. Làm sạch bộ nhớ đệm
  2. Bấm một chức năng
  3. Xem SQL phát sinh
  4. Chọn SQL trả số liệu
  5. Lấy tham số và kiểm chứng

Tổng quan

Mỗi lần người dùng bấm một chức năng, ứng dụng gửi một hoặc nhiều câu SQL tới PostgreSQL. PostgreSQL lưu các câu này trong các view thống kê như pg_stat_statements và pg_stat_activity kèm thời điểm chạy và số dòng trả về. Nếu chỉ có một người thao tác trong một khoảng thời gian ngắn, ta có thể lọc theo thời gian để biết chính xác chức năng đó đã sinh ra những SQL nào.

Chỉ thực hiện trên môi trường test

Hướng dẫn này có lệnh làm sạch bộ nhớ đệm và bật log, có thể ảnh hưởng hiệu năng nếu chạy trên môi trường đang vận hành.

Điều kiện và chuẩn bị

  • Môi trường test, chỉ một người thao tác ứng dụng trong suốt thời gian lấy.
  • Tài khoản superuser hoặc tài khoản được đọc pg_stat_activity, pg_stat_statements, pg_stat_user_tables.
  • Biết user PostgreSQL mà ứng dụng dùng để kết nối. Trong tài liệu này dùng ví dụ app_user; hãy thay bằng user thực tế.
  • Công cụ chạy SQL: pgAdmin, DBeaver hoặc psql.
  • Đã cài extension pg_stat_statements (xem Bước 3).

2

Xác định backend của ứng dụng

Cho ứng dụng đăng nhập và để ở trạng thái chờ, chưa bấm gì. Sau đó chạy:

SQL
SELECT pid, usename, application_name, client_addr, backend_start, state
FROM   pg_stat_activity
WHERE  usename = 'app_user'
ORDER  BY backend_start DESC;

Nếu ứng dụng dùng connection pool, bạn sẽ thấy nhiều backend. Cứ ghi lại tất cả; Bước 3 và 7 không phụ thuộc vào một backend cụ thể.

3

Làm sạch bộ nhớ đệm Chỉ trên test

PostgreSQL không có lệnh FLUSH SHARED_POOL như Oracle. Thay vào đó, ta reset thống kê của pg_stat_statements để mọi SQL xuất hiện sau đó chắc chắn đến từ thao tác của bạn:

SQL
SELECT pg_stat_statements_reset();

Nếu chưa cài extension, chạy:

SQL
CREATE EXTENSION IF NOT EXISTS pg_stat_statements;
-- Sau đó thêm 'pg_stat_statements' vào shared_preload_libraries
-- trong postgresql.conf và khởi động lại PostgreSQL.

Nếu không được phép chạy lệnh này, bỏ qua bước 3 và dựa vào mốc thời gian ở Bước 4 và 6.

7

Liệt kê SQL phát sinh

Khi chạy, công cụ sẽ hỏi giá trị t0 và t1; nhập đúng định dạng YYYY-MM-DD HH24:MI:SS.

SQL
SELECT queryid, calls, rows,
       ROUND(total_exec_time::numeric, 2) AS total_time_ms,
       ROUND(mean_exec_time::numeric, 2)  AS mean_time_ms,
       SUBSTR(query, 1, 150) AS query_preview
FROM   pg_stat_statements
WHERE  query ILIKE '%SELECT%'
  AND  query NOT ILIKE '%pg_stat%'
  AND  query NOT ILIKE '%pg_catalog%'
  AND  query NOT ILIKE '%information_schema%'
ORDER  BY total_exec_time DESC
LIMIT  50;

Nếu ứng dụng kết nối dưới user khác, hãy lọc thêm bằng usename trong pg_stat_activity hoặc dùng pg_stat_statements kết hợp với pg_stat_activity để lọc theo userid.

Để lọc theo thời gian chính xác hơn, dùng pg_stat_activity:

SQL
SELECT pid, usename, application_name, state,
       query_start, state_change,
       SUBSTR(query, 1, 200) AS query_preview
FROM   pg_stat_activity
WHERE  usename = 'app_user'
  AND  query_start BETWEEN TO_TIMESTAMP('&t0','YYYY-MM-DD HH24:MI:SS')
                       AND TO_TIMESTAMP('&t1','YYYY-MM-DD HH24:MI:SS')
ORDER  BY query_start;
8

Chọn SQL “trả số liệu”

Một lần bấm thường sinh từ 3 đến 20 SQL. Giữ lại câu SQL thoả các điều kiện sau:

  • Bắt đầu bằng SELECT hoặc WITH.
  • Truy vấn bảng nghiệp vụ (doanh thu, đơn hàng, khách hàng...), không phải bảng cấu hình, phân quyền, menu hay log.
  • rows lớn hơn 0 và hợp lý: báo cáo tổng hợp thì ít dòng, danh sách chi tiết thì nhiều dòng.
  • Thường là SQL có total_exec_time lớn nhất, và chứa các cột giống tiêu đề cột trên báo cáo.

Lấy toàn văn SQL đã chọn:

SQL
SELECT query
FROM   pg_stat_statements
WHERE  queryid = &queryid;
9

Lấy giá trị tham số (bind)

PostgreSQL không có view bind capture như Oracle. Có hai cách:

Cách 1: Dùng pg_stat_statements với chế độ hiển thị tham số

SQL
-- Xem query đã được chuẩn hoá (có $1, $2...)
SELECT query
FROM   pg_stat_statements
WHERE  queryid = &queryid;

Cách 2: Bật log tham số bind (chỉ trên test)

SQL
-- Trong phiên hiện tại
SET log_min_duration_statement = 0;
SET log_statement = 'all';
SET log_parameter_max_length = -1;  -- log toàn bộ tham số bind
Lưu ý

Việc bật log toàn bộ tham số có thể ghi log rất nhiều. Chỉ bật trong thời gian ngắn và tắt ngay sau khi lấy xong.

10

Chỉ khi số liệu khớp mới coi đó là đúng cặp.

Nếu một chức năng cần nhiều SQL mới ra số liệu, lưu thành một yêu cầu gồm nhiều SQL có thứ tự (1, 2, 3...).

Cách bắt bằng log (khi cần chắc chắn về giá trị bind)

Dùng thay cho các Bước 3 đến 7, hoặc chạy song song để bổ sung giá trị tham số.

a. Bật log trước khi bấm

SQL
ALTER SYSTEM SET log_statement = 'all';
ALTER SYSTEM SET log_min_duration_statement = 0;
ALTER SYSTEM SET log_parameter_max_length = -1;
SELECT pg_reload_conf();

b. Bấm đúng một chức năng

Thực hiện như Bước 5.

c. Tắt log

SQL
ALTER SYSTEM RESET log_statement;
ALTER SYSTEM RESET log_min_duration_statement;
ALTER SYSTEM RESET log_parameter_max_length;
SELECT pg_reload_conf();

d. Tìm file log

SQL
SHOW log_directory;
SHOW log_filename;
SHOW data_directory;

File log thường nằm trong <data_directory>/log/ hoặc /var/log/postgresql/ tuỳ hệ điều hành.

e. Đọc file log

  • Mở file log bằng trình soạn thảo văn bản. Tìm các dòng có statement: (câu SQL) và parameters: (giá trị tham số).
  • Hoặc dùng pg_read_file (nếu có quyền):
SQL
SELECT pg_read_file('log/postgresql.log', 0, 1000000);
Lưu ý về pg_stat_statements

pg_stat_statements chỉ lưu câu SQL đã chuẩn hoá (với $1, $2...), không lưu giá trị tham số cụ thể. Muốn thấy bind phải đọc file log gốc hoặc dùng auto_explain.

Quá nhiều SQL lẫn lộnCó người khác đang dùng ứng dụng hoặc có job nền. Làm lại khi chỉ có một người thao tác.
SQL chứa giá trị cố định (như '202609') thay vì $1Ứng dụng nối chuỗi. Tự thay giá trị thành bind khi lưu; dùng queryid trong pg_stat_statements để gộp các biến thể.

Dọn dẹp sau khi hoàn tất

  • Đảm bảo log đã được tắt (bước c ở phần Trace).
  • Xoá file log nếu chứa dữ liệu nhạy cảm.
  • Lưu phiếu ghi chép cùng cặp thông tin đã lấy.
Tài liệu hướng dẫn nội bộ. Ví dụ dùng user app_user; thay bằng thông tin thực tế của môi trường.
