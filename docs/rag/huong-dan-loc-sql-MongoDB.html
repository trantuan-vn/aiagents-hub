Hướng dẫn lọc một cặp “Tên yêu cầu số liệu – Query” từ ứng dụng MongoDB

Bấm đúng một chức năng, báo cáo hoặc tra cứu trên ứng dụng, bắt lại các câu query mà MongoDB vừa chạy, rồi chọn ra câu query trả số liệu để lưu thành một cặp có định danh.

  1. Bật profiler
  2. Bấm một chức năng
  3. Xem query phát sinh
  4. Chọn query trả số liệu
  5. Lấy tham số và kiểm chứng
  6. Lưu thành cặp

Tổng quan

Mỗi lần người dùng bấm một chức năng, ứng dụng gửi một hoặc nhiều lệnh tới MongoDB (thường qua driver: find, aggregate, count...). MongoDB có thể ghi lại các lệnh này vào collection system.profile nhờ Database Profiler, kèm thời điểm chạy, thời gian thực thi và số document trả về. Nếu chỉ có một người thao tác trong một khoảng thời gian ngắn, ta có thể lọc theo thời gian để biết chính xác chức năng đó đã sinh ra những query nào.

Chỉ thực hiện trên môi trường test

Hướng dẫn này có lệnh bật profiler ở mức 2 (ghi tất cả), có thể ảnh hưởng hiệu năng và sinh nhiều dữ liệu nếu chạy trên môi trường đang vận hành.

Điều kiện và chuẩn bị

  • Môi trường test, chỉ một người thao tác ứng dụng trong suốt thời gian lấy.
  • Tài khoản có quyền dbAdmin hoặc clusterMonitor trên database cần theo dõi (để bật profiler và đọc system.profile).
  • Biết tên database và tên user MongoDB mà ứng dụng dùng để kết nối. Trong tài liệu này dùng ví dụ database appdb, user app_user; hãy thay bằng thông tin thực tế.
  • Công cụ chạy lệnh: mongosh (MongoDB Shell), MongoDB Compass hoặc mongo legacy shell.
  • Biết replica set / shard nếu ứng dụng kết nối tới cluster (profiler phải bật trên từng node cần theo dõi).

Xác định connection của ứng dụng

Cho ứng dụng đăng nhập và để ở trạng thái chờ, chưa bấm gì. Sau đó chạy trong mongosh:

JavaScript
db.adminCommand({ currentOp: 1, $all: true })
// Hoặc lọc gọn hơn:
db.currentOp({ "effectiveUsers.user": "app_user" })

Nếu ứng dụng dùng connection pool, bạn sẽ thấy nhiều connection. Cứ ghi lại appName, client, connectionId; Bước 3 và 7 không phụ thuộc vào một connection cụ thể.

3

Bật Database Profiler Chỉ trên test

Bật profiler ở mức 2 để ghi tất cả thao tác vào collection system.profile:

JavaScript
// Chuyển sang database của ứng dụng
use appdb

// Bật profiler mức 2 (ghi tất cả thao tác)
db.setProfilingLevel(2)

// Kiểm tra
db.getProfilingStatus()

Nếu collection system.profile đã có dữ liệu cũ, xoá trước để dễ lọc:

JavaScript
db.system.profile.drop()
db.createCollection("system.profile", { capped: true, size: 100 * 1024 * 1024 })

Nếu không được phép bật profiler, bỏ qua bước 3 và dựa vào $currentOp ở phần Cách bắt bằng $currentOp.

7

Liệt kê query phát sinh

Khi chạy, công cụ sẽ hỏi giá trị t0 và t1; nhập đúng định dạng ISO (YYYY-MM-DDTHH:mm:ss.sssZ).

JavaScript
db.system.profile.find({
  ts: { $gte: ISODate("&t0"), $lte: ISODate("&t1") },
  op: { $in: ["query", "command", "getmore"] },
  ns: { $not: /\.system\./ }
}).sort({ ts: 1 }).forEach(doc => {
  print(JSON.stringify({
    ts: doc.ts,
    op: doc.op,
    ns: doc.ns,
    millis: doc.millis,
    nreturned: doc.nreturned,
    planSummary: doc.planSummary,
    command: doc.command
  }, null, 2))
})

Nếu ứng dụng dùng user khác hoặc database khác, hãy lọc thêm bằng ns (namespace db.collection) hoặc appName / client trong system.profile.

Hoặc xem gọn dạng bảng:

JavaScript
db.system.profile.find({
  ts: { $gte: ISODate("&t0"), $lte: ISODate("&t1") },
  op: { $in: ["query", "command", "getmore"] }
}).sort({ ts: 1 }).limit(50).pretty()
8

Chọn query “trả số liệu”

Một lần bấm thường sinh từ 3 đến 20 lệnh. Giữ lại lệnh thoả các điều kiện sau:

  • op là query, command (thường là find, aggregate, count) hoặc getmore.
  • Truy vấn collection nghiệp vụ (doanh thu, đơn hàng, khách hàng...), không phải collection cấu hình, phân quyền, menu hay log.
  • nreturned lớn hơn 0 và hợp lý: báo cáo tổng hợp thì ít document, danh sách chi tiết thì nhiều document.
  • Thường là lệnh có millis lớn nhất, và có command chứa các trường giống tiêu đề cột trên báo cáo (aggregate pipeline, $group, $project, ...).

Lấy toàn văn lệnh đã chọn:

JavaScript
db.system.profile.find({
  ts: ISODate("&ts"),
  ns: "&ns"
}).forEach(doc => {
  printjson(doc.command)
})
9

Lấy giá trị tham số (bind)

MongoDB không có khái niệm bind variable như SQL. Giá trị tham số nằm trực tiếp trong command dưới dạng filter/pipeline. Để trích ra:

JavaScript
const doc = db.system.profile.findOne({
  ts: ISODate("&ts"),
  ns: "&ns"
})
printjson(doc.command)

Với lệnh aggregate, xem command.pipeline và command.cursor. Với find, xem command.filter, command.sort, command.projection.

Lưu ý về driver

Nhiều driver dùng $db command với find / aggregate dạng chuỗi. Profiler ghi lại đúng những gì driver gửi. Nếu giá trị tham số bị driver mã hoá hoặc nối chuỗi, bạn sẽ thấy giá trị cố định trong command.

10

Kiểm chứng kết quả Bắt buộc

Chạy lại lệnh trong mongosh hoặc MongoDB Compass, thay giá trị tham số đúng như đã lấy, rồi so sánh với màn hình đã chụp ở Bước 5.

JavaScript
// Ví dụ với aggregate
db.doanhthu.aggregate([
  { $match: { thang: "202609", chi_nhanh: 10 } },
  { $group: { _id: null, tong: { $sum: "$so_tien" } } }
])

Chỉ khi số liệu khớp mới coi đó là đúng cặp.

Cách bắt bằng $currentOp (khi cần xem query đang chạy)

Dùng thay cho các Bước 3 đến 7, hoặc chạy song song để bổ sung. Cách này chỉ thấy query đang chạy, không thấy query đã chạy xong.

a. Bật theo dõi trước khi bấm

JavaScript
// Xem tất cả operation đang chạy
db.adminCommand({
  currentOp: 1,
  $all: true,
  active: true
})

b. Bấm đúng một chức năng

Thực hiện như Bước 5. Trong lúc chờ kết quả, chạy lại lệnh $currentOp để bắt query đang chạy.

c. Lọc theo user / appName

JavaScript
db.adminCommand({
  currentOp: 1,
  $all: true,
  "effectiveUsers.user": "app_user"
})

d. Đọc kết quả

  • op: loại thao tác (query, command, getmore...).
  • ns: namespace (db.collection).
  • command: nội dung lệnh, gồm filter/pipeline.
  • secs_running: số giây đã chạy.
  • planSummary: kiểu plan (COLLSCAN, IXSCAN...).
Lưu ý về profiler vs $currentOp

$currentOp chỉ bắt được query đang chạy tại thời điểm gọi. Nếu query chạy nhanh, bạn có thể bỏ lỡ. Profiler (Bước 3) ghi lại mọi query đã chạy, phù hợp hơn cho mục đích lọc cặp.

Dọn dẹp sau khi hoàn tất

  • Tắt profiler: db.setProfilingLevel(0).
  • Xoá collection system.profile nếu chứa dữ liệu nhạy cảm: db.system.profile.drop().
  • Lưu phiếu ghi chép cùng cặp thông tin đã lấy.
Tài liệu hướng dẫn nội bộ. Ví dụ dùng database appdb và user app_user; thay bằng thông tin thực tế của môi trường.
